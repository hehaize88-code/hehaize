PikoBuy Jersey Spreadsheet: Sizing, Customization and QC

A jersey row must identify the exact version, preserve the size basis and make every custom character reviewable. This field system connects a live listing to order notes and warehouse evidence without promising fit, authenticity or print durability.

Start with the jersey version, not the headline

“Home jersey, size L” is too vague for an order record. One listing may place adult and youth cuts, short and long sleeves, player-labelled and fan-labelled versions, shirt-only and set options, or several seasons in the same menu. Those labels are seller-defined, not universal specifications. Your first fields should preserve the marketplace, final seller URL, product identifier, store name, original listing title and the date checked.

Next, copy the complete option path that produces the intended item: version wording, colour or edition, sleeve choice, size, included pieces, customization branch and quantity. Save the displayed price only after that path is selected. PikoBuy's current guide instructs buyers to confirm specifications, colour and size, then choose specifications, colour, size and quantity when submitting an order; it also notes that the actual purchase price governs. A thumbnail price or shortened title cannot replace the selected configuration.

Keep the original option text beside a concise English note to reduce translation drift. Mark the row live, ambiguous, unavailable, replaced or unchecked. “Live” means the exact option appeared when reviewed; it does not certify stock, licensing or quality.

Turn the size chart into traceable evidence

Never convert a jersey size from another brand or listing by letter alone. Save the chart image or values with the product ID, version, units and check date. Record whether it appears to describe the garment or a recommended body range. If that distinction is not stated, mark it unknown rather than choosing the interpretation that makes a size look suitable.

Each measurement needs a named path. Useful fields may include flat chest width, front or back length, shoulder width, sleeve length, hem width and, for a set, shorts waist and outseam. Only compare numbers whose endpoints match. “Length 74 cm” is incomplete if one seller measures from the highest shoulder point and another starts at the collar seam.

Create a reference-garment block for a jersey or shirt that already fits as intended. Store its description, the date measured, whether it was laid flat and relaxed, and the same start and end points used by the listing. A useful entry reads “flat chest, underarm seam to underarm seam, straight across, centimetres.” A reusable reference is stronger than a generic regional conversion, although fabric stretch, cut and personal preference still prevent a fit guarantee.

When measurement evidence conflicts, do not average it. Keep the seller chart, listing diagram and later warehouse measurement in separate columns. Expose the disagreement so the buyer can ask a precise question.

Treat customization as a controlled specification

If a listing offers a name, number, badge, patch or other personalized choice, treat each as its own field. Record whether the selected option is stock printed, seller-customized or unclear. Then preserve the exact text, capitalization, punctuation, spacing, accents and number sequence. A note saying “same as message” is not an auditable specification.

For a custom name, add the character count and a second reviewer field. Distinguish front, back and sleeve numbers when offered. Save seller-written patch names and locations instead of inferring an edition from a small image. If customization changes price, record the final selection state.

PikoBuy's current terms advise buyers of custom-made products to negotiate with the merchant and provide the platform with the merchant contact details after successful negotiation. They also state that PikoBuy cannot professionally inspect custom-made products. Save the question, answer date, agreed spelling, number, placements and any image the seller explicitly accepted. Do not treat silence or an automated status as artwork approval.

Customization also changes the exit plan. PikoBuy's current returns page says customized products are not automatically supported for no-reason returns, and eligibility depends on the seller and condition. Confirm current terms before ordering, and keep packaging, labels and accessories intact while a decision is pending.

Write order notes that another person can execute

Build the note from structured cells instead of drafting it from memory at checkout. The instruction should identify the product and exact variant first, then customization, prohibited substitutions and any question that must be answered before purchase. Keep politeness outside the specification so the critical text is easy to scan.

  1. Identity: final URL, product ID and original listing title.
  2. Variant: exact version, colour or edition, sleeve, size, set contents and quantity.
  3. Customization: exact name, number and seller-labelled patch choices; write “none” where deliberately blank.
  4. Placement: only the locations offered or explicitly confirmed by the seller.
  5. Do not substitute: state which size, version, print or set change requires approval.
  6. QC focus: list a few observable checks that can change the keep-or-return decision.

Before submitting, compare the imported PikoBuy title, selected specifications, colour, size, quantity and price with the saved row. Timestamp that comparison. If any field differs, pause and resolve it rather than adding a corrective note to the wrong option.

Design QC around decisions the photos can support

PikoBuy's guide describes warehouse check-in, photo confirmation and defect checking. Its shipping terms say buyers can view inspection photos and may request additional detailed photos, while professional inspection is unavailable for some products. Plan a short evidence sequence without assuming a fixed photo count or laboratory-level verification.

First establish identity: front and back views, selected colour or edition, size label, sleeve choice, included shorts or accessories, and all intended customization. Compare each custom character against the saved specification. Check visible placement, orientation, major alignment, missing elements, obvious damage and whether a patch option appears in the agreed location.

Second review construction that is visible at warehouse-photo scale: neckline shape, panel matching, hems, seam continuity, loose or broken stitching, print edges, puckering, stains, holes and major colour inconsistency. A photo may reveal a problem, but it cannot prove fibre percentages, licensing, authenticity, stretch recovery, wash resistance, breathability or long-term print adhesion. Record “not verifiable” rather than upgrading appearance into a material conclusion.

Third request a measurement only when the result changes the decision. State the garment position, endpoint, units and tolerance used in your own acceptance rule. The visible tape should begin and end at the named points where feasible. NIST's explanation of tape accuracy highlights the importance of calibration and repeatable measurement; in an order record, repeatable endpoints are the practical control you can specify.

Append the warehouse date, evidence received, observed result and decision. Never overwrite the seller claim or pre-order instructions. The difference between promised configuration and received evidence is the purpose of the QC record.

Worked comparison: stock print versus custom text

Consider two hypothetical listings for the same general jersey style. Listing A offers a preprinted name-and-number option, a shirt-only version and a size chart with chest and back-length endpoints. Listing B offers lower-priced blank and customized branches plus an optional shorts set, but its chart does not identify whether length is measured from the shoulder or collar.

  1. Create two rows; preserve both product IDs, seller names, original titles and review dates.
  2. For A, record the complete preprinted option text, shirt-only contents and chart endpoints. Do not reclassify the printed identity from the listing image.
  3. For B, record the blank or custom branch, set choice and final selected price separately. Mark the length endpoint unknown.
  4. Compare A's chart with the reference garment only where the endpoints match. Send B one concise endpoint question.
  5. If choosing B customization, copy the exact name, number, case and patch choice into dedicated cells and obtain seller confirmation before purchase.
  6. Give A a QC check for the correct stock print. Give B character-by-character checks plus the agreed placement and set contents.
  7. Keep both rows in research until size evidence and intended configuration meet the acceptance rules.

The custom listing is not automatically better because it offers more control, and the stock print is not automatically safer because it needs fewer instructions. The stronger row is the one whose exact product, fit evidence and received configuration can be checked without guessing.

Use three gates before marking the row ready

Configuration gate: the live source, exact version, size, contents, custom text and selected price state all match. Evidence gate: the chart basis is usable, critical seller questions are answered and unknowns are explicit. Exit gate: the buyer has read the current customization and return conditions, defined observable QC priorities and avoided irreversible handling before the keep-or-return decision.

Mark the row order-ready only after all three gates pass. Use research when one seller answer, matching endpoint or customization confirmation could resolve the choice. Use reject when the required option is unavailable, the size evidence cannot support the intended decision, or the seller will not confirm a must-have custom detail.

A PikoBuy jersey spreadsheet is valuable because it preserves decisions through change. The listing can be edited, a price can move and a message can be forgotten. The row retains what was selected, what was confirmed, what the warehouse could actually show and which uncertainty remained acceptable.
