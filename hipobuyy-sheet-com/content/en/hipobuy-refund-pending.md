A Hipobuy refund marked Under Review is different from a completed return, a wallet credit or a withdrawal to a payment method. Start by identifying which stage is unresolved. Keep the order, return request and account transaction records together, then ask about the specific missing step instead of treating every pending status as the same delay.

## Identify the transaction you are checking

Start with one order and one requested outcome. You might be cancelling an unfulfilled purchase, returning a warehoused item, checking a refund already recorded in the account or asking about a separate withdrawal. These actions can involve different records. A seller return tracking number will not necessarily explain a wallet transaction, and a bank statement alone cannot tell you whether the item return was approved. Identify the record responsible for the next step.

Save the order identifier, selected variant, amount actually paid and request timestamp. If several items were purchased together, establish whether the request concerns one item or the whole set. Keep the displayed currency with every amount. Two numbers can look different because one belongs to a partial return or a different transaction. Our [payment and wallet guide](/en/articles/fees-wallet-payment/) explains why product payments and later international shipping should be recorded separately.

## Read the official status descriptions carefully

Hipobuy's official order-status page says Canceled orders are refunded to the Hipobuy wallet. It describes Under Review as a refund application being processed until the return is completed, and Returned as completion of the return and refund process with funds sent to the Hipobuy account. These descriptions do not establish a universal completion time, and an account credit is not proof of money reaching an external card or bank account.

| Record or status | What to check | What it does not prove |
| --- | --- | --- |
| Cancellation requested | Whether cancellation was accepted | A completed refund |
| Under Review | The unresolved return or review step | An external payment is on its way |
| Returned | The matching account refund transaction | A withdrawal to your original payment method |
| Wallet credit visible | Amount, currency and order reference | That a separate withdrawal was requested |
| Withdrawal request | Its own status and applicable terms | A guaranteed arrival date |

## Check return eligibility before interpreting a delay

A request can depend on the seller, item condition and applicable window. Hipobuy's returns page sets a five-day, 120-hour request period starting the next hour after the order becomes Warehoused, alongside eligibility conditions. Custom-made items and products whose packaging, tags or accessories were removed at the user's request can fall outside the normal guarantee. Check the current terms and the specific response for your item rather than assuming every request must be accepted.

If the request is still within an applicable window, preserve the time and submit the relevant evidence promptly. If it has already been submitted, keep the confirmation rather than relying on the time you first discussed the issue elsewhere. Storage availability is a separate matter and does not establish a longer return period. See the [warehouse return guide](/en/articles/return-policy-warehouse/) for eligibility details; this page focuses on following the transaction after a request exists.

## Locate the missing step in the return record

Read the latest message for an explicit requirement: clarification of the reason, photographs, seller approval, return postage or another action. Separate a request for information from a simple processing status. If a return shipment exists, keep its identifier and delivery evidence with the case. A parcel delivered to the seller is one milestone; it does not, on its own, confirm that the account refund entry has been posted. Ask which stage remains outstanding.

Avoid inventing a deadline by borrowing another buyer's experience. Different sellers, request reasons and payment records can follow different sequences. If support has supplied a case-specific follow-up date, save it and refer to it when necessary. If no useful timeframe is given, ask what event is expected next and when to check again. That creates an answerable question without claiming the platform has missed a service promise that was never stated.

## Reconcile the amount rather than assuming a full repayment

Compare the actual product payment with the refund entry and any stated deductions. The returns page says the refund is based on the amount actually paid and describes return costs, including a possible RMB 5 service fee for an unconditional return. Its shipping wording varies across sections, so confirm the specific outbound and return postage treatment with the order handler instead of treating a generic formula as your final settlement. Ask for an itemised explanation where needed.

An illustrative worksheet might start with a product payment of 100 units, then record a refund of 90 and an explained 10-unit deduction. Those numbers are not Hipobuy prices or a fee schedule. Their purpose is to make a difference visible. Keep shipping, optional services, currency conversion and separate purchases on their own lines. A mismatch should lead to a request for the transaction breakdown rather than an unsupported assumption about where the money went.

## Separate a wallet credit from an external withdrawal

If the order says Returned, look for the corresponding transaction in the Hipobuy account before checking only the original payment card. Record the credit amount, date, currency and reference. A wallet credit and a withdrawal are different events. Do not assume the platform automatically sends every refund back to the original payment method merely because the product return is complete. Read the current account options and ask support if the destination is unclear.

If you have separately requested a withdrawal, use that request's own reference and status. Check the available method, any displayed terms and the explanation for a failure or pending state. This guide cannot supply an unverified withdrawal fee, processing period or payment destination. Avoid making repeated requests merely to test whether one succeeds; first establish what happened to the existing request and whether another action is actually required.

## Prepare one concise support record

Include the order reference, return request date, current status, latest relevant message, product payment and any refund transaction already visible. State the unresolved question clearly: seller approval, return shipment, missing account credit, unexplained deduction or separate withdrawal. Attach only evidence that addresses that question. A cropped transaction or status screenshot is usually more useful than several unrelated pages with no explanation of which number is in dispute.

Keep passwords, verification codes, full payment-card details and public address labels out of the record. Send necessary account information through official support, not a public comment or an unrelated coupon site. Retain the reply and any case reference. When following up, explain what remains unresolved and what has changed since the previous response. Consistent identifiers make it easier to distinguish a genuinely missing credit from a different item or payment.

## Close the case with a matched outcome

Treat the case as resolved only when the outcome you requested can be matched to the relevant record. That may be a cancellation confirmation and wallet credit, a completed return and agreed settlement, or a separate withdrawal completed through the stated method. Save the evidence together. If you decide to keep an item after discussion, record that decision too so that an old return request is not confused with the current plan.

For future orders, save the exact variant, product payment, warehouse arrival time and any QC concern as they occur. Those records make a later return easier to explain. Review [missing QC evidence](/en/articles/hipobuy-qc-photos-not-showing/) before approving shipment, and settle known item issues before combining products into an international parcel. A clear paper trail improves the quality of the support request; it does not guarantee seller approval, a particular refund amount or a fixed completion date.
